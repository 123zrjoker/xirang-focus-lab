# 1.0.0 正式发布实施计划

> 规划日期：2026-09-21
> 前置版本：0.9.0
> 状态：发布收尾（本地正式候选、覆盖升级及两轮远端 Windows CI 通过；正在冻结最终发布提交）
> 阶段目标：在不增加核心功能的前提下，把已经通过本地与远端门禁的 0.9.0 候选提升为可安装、可复现、可核验的 1.0.0 正式版本。

## 1. 固定边界

- 1.0.0 不新增训练、专注、待办、知识库或 Agent 核心功能，只处理正式发布阻塞问题。
- API、业务状态、备份、知识库和 Agent Checkpoint 继续使用 0.9.0 已冻结的兼容矩阵；若必须改变契约，停止发布并重新执行迁移设计。
- 最终用户验收使用隔离数据目录和脱敏合成数据，不触碰用户真实数据或真实 API Key。
- 安装包、Portable、sidecar 与升级验收必须由同一最终提交构建；重新构建后必须重新计算 SHA-256。
- 本地完整门禁、远端 Windows CI 和最终标签必须指向同一候选提交。
- 本阶段不修改或编写简历；未经授权不创建 `v1.0.0` 标签、GitHub Release 或上传制品。

## 2. 实施顺序

### 1.0.0-a 版本、契约与发布记录（已完成）

- 建立 `docs/contracts/1.0.0-runtime-contract.json`，保持 API 与数据契约兼容。
- 将应用、锁文件、Python API 和桌面烟测默认制品统一升至 1.0.0。
- 让 `release:check` 根据当前应用版本读取对应契约清单，避免后续版本继续硬编码 0.9.0。
- 建立变更记录和 1.0.0 验收报告入口。

### 1.0.0-b 最终用户路径验收（自动化路径已通过）

- 在全新隔离数据空间验证训练、专注、待办、笔记、知识库导入/检索、备份恢复和 Agent 审批边界。
- 验证无 Key、API 不可达和模型不可用时的降级路径，不把离线替身描述为真实模型结果。
- 对关键界面执行键盘、焦点、语义名称和错误恢复复验。

### 1.0.0-c Windows 正式候选（已完成）

- 构建 1.0.0 sidecar、unpacked、NSIS 和 Portable。
- 验证首次安装、启动、退出回收、卸载，以及 0.9.0 → 1.0.0 覆盖升级。
- 验证 DPAPI 凭据、Qdrant 索引、SQLite Checkpoint 和 Electron 用户数据目录保留。

### 1.0.0-d 完整门禁与发布证据（已完成）

- 运行完整质量、Agent Eval、性能、无障碍和独立安全门禁。
- 冻结正式候选制品 SHA-256，记录已知限制和证据边界。
- 推送最终候选分支并等待远端 Windows 质量与安全 Job 通过。

### 1.0.0-e 正式发布（待授权）

- 核对候选提交、远端分支、制品哈希与 CI 运行一致。
- 获得授权后创建并推送 `v1.0.0` 标签。
- 仅在另行获得授权时创建 GitHub Release 和上传安装制品。

## 3. 完成定义

1. 1.0.0 版本、API 和数据契约由自动检查约束且无漂移。
2. 最终用户关键路径在隔离数据空间通过，失败路径可恢复且不泄露私人数据。
3. 0.9.0 → 1.0.0 覆盖升级、首次安装、Portable、退出和卸载通过。
4. 本地与远端完整质量、安全、性能和无障碍门禁通过。
5. 正式候选制品哈希、变更记录、复现说明和已知限制齐全。
6. `v1.0.0` 只指向满足以上条件的最终候选提交。
