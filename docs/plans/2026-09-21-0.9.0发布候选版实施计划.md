# 0.9.0 发布候选版实施计划

> 规划日期：2026-09-21
> 前置版本：0.8.0
> 状态：实施中（契约、迁移与故障降级自动化已通过；下一步为 Windows 候选包升级验收）
> 阶段目标：冻结发布所依赖的数据和 API 契约，验证旧数据升级、离线降级、Windows 安装升级、无障碍与全链路回归，只修复发布阻塞问题。

## 1. 固定边界

- 0.9.0 不新增核心业务功能，不改变 Agent 的人工审批、数据所有权或 Mutation Intent 安全语义。
- 源码验证批次保持 0.8.0；进入受控安装包验收前统一升级到 0.9.0 以生成真实候选产物，但只有全部候选门禁满足后才允许创建正式标签。
- 业务状态、备份、知识库和 Agent Checkpoint 的兼容范围必须由可机读契约与自动测试共同约束，不能只依赖文档描述。
- 旧数据迁移必须保留用户记录；遇到未来版本或未知契约时失败关闭，不允许静默覆盖。
- 无 API Key、模型不可用、本机 API 不可达或索引未就绪时，非 AI 的训练、专注、待办、笔记和备份能力仍应可用。
- 安装、覆盖升级和卸载测试必须使用受控目录，不触碰用户真实数据目录。
- 用户已明确本阶段不修改或编写简历。

## 2. 实施批次

### 0.9.0-a 契约清单与版本一致性（已完成）

- 建立 `docs/contracts/0.9.0-runtime-contract.json`，冻结 API、业务状态、备份、知识库与 Agent 契约版本。
- 增加 `release:check`，校验前端、锁文件、Python API 和契约清单的版本一致性，并加入 `quality:gate`。
- 在 `/api/health` 和 `/api/diagnostics` 中公开稳定的 API 契约版本，不暴露凭据或私人数据。
- 修复 0.8.0 前端版本与 Python API 版本漂移。

### 0.9.0-b 旧数据迁移与备份恢复（自动化已完成，待随候选包验证覆盖升级）

- 建立业务状态 v1、v8-v11、备份格式 v1-v2、知识库 v1-v2 和 Agent 旧 Checkpoint 的固定兼容矩阵。
- 验证完整备份的往返恢复、未来版本拒绝、无效引用拒绝和恢复失败不破坏现有数据。
- 验证覆盖升级后 SQLite Checkpoint、DPAPI 凭据、Qdrant 索引和前端业务数据的保留边界。

### 0.9.0-c 离线与故障降级（已完成）

- 覆盖无 Key、模型缺失、API 启动失败、API 中途退出、索引未就绪和网络调用失败。
- 保证核心本地功能可继续使用，并给出可操作、不会泄露路径或凭据的恢复提示。
- 验证重启本机服务不会重复副作用或破坏待审批 Agent 线程。

### 0.9.0-d Windows 安装、升级与卸载（下一批次）

- 生成 0.9.0 候选 sidecar、unpacked、NSIS 和 Portable 产物。
- 在受控目录验证 0.8.0 到 0.9.0 覆盖升级、首次启动、退出回收和卸载。
- 冻结安装产物、blockmap、Portable 与 sidecar 的 SHA-256。

### 0.9.0-e 无障碍与全链路回归（自动化已通过，待候选包复验）

- 检查主要导航、设置、数据导入、Agent 审批和训练关键路径的键盘可达性、焦点可见性、语义名称与动态状态播报。
- 运行合成数据导入、Fake Agent Eval、完整质量门禁、安全门禁及关键桌面业务串联。
- 只修复阻塞发布的问题，不增加新的核心范围。

### 0.9.0-f 候选冻结

- 确认产品版本已统一为 0.9.0，更新路线图、变更记录和候选验收报告。
- 推送分支并等待远端质量与安全 Job 通过。
- 只有候选验收无阻塞缺陷时才创建 `v0.9.0` 标签。

## 3. 当前门禁记录（2026-09-21）

- `release:check`：通过；前端、桌面、Python API、备份、业务状态、知识库与 Agent 兼容矩阵均与契约清单一致。
- 前端单元测试：12 个文件、72 项全部通过。
- 桌面监督测试：10 项全部通过，覆盖 sidecar 版本/协议不兼容、启动失败、中途退出和重启恢复。
- Python 测试：68 项全部通过，旧 Agent 图版本可在 SQLite 重启后恢复，未知版本失败关闭。
- `qa:accessibility`：通过；隔离 Electron 数据空间验证模态初始焦点、Tab 约束、Esc 关闭、焦点归还与未来数据只读保护。
- 构建、Fake Agent Eval 和 API 性能门禁：通过；最终候选仍需在统一升版后重新执行质量与安全门禁。
- 下一项：进入 0.9.0-d，统一候选版本后生成 sidecar、unpacked、NSIS 与 Portable，在受控目录执行 0.8.0 → 0.9.0 覆盖升级和卸载验收。

## 4. 完成定义

1. 版本、API 和数据契约存在可机读单一清单，并由 CI 自动检查。
2. 支持范围内的旧业务数据、知识库和 Checkpoint 均有固定迁移测试；未来版本失败关闭。
3. AI、本机 API 或模型不可用时，核心本地功能仍可用且提示可恢复。
4. 0.8.0 到 0.9.0 的 Windows 覆盖升级、卸载和数据保留在受控环境通过。
5. 关键路径完成键盘与基础无障碍验收。
6. 本地与远端完整质量、安全、性能和桌面门禁全部通过，无发布阻塞缺陷。
