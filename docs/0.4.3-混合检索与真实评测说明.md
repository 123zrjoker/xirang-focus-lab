# 0.4.3 混合检索与真实评测说明

> 目标：把 0.4.0 的关键词实验台推进为一条本机可运行、结果可解释、指标可复现的 RAG 检索链路。当前只负责找依据，不生成答案。

## 检索链路

1. 浏览器从已授权知识来源读取可追溯文本块。
2. 用户明确构建索引后，FastAPI 使用 `BAAI/bge-small-zh-v1.5` 在 CPU 上生成 512 维归一化向量，并写入 Qdrant local mode。
3. 查询时 BM25 与 BGE 各召回前 20 条；RRF 使用 `k=60` 和等权配置融合排名。
4. “混合 + 重排”模式使用 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` 的量化 ONNX 模型联合编码查询与前 12 条候选，然后按相关性分数重排。
5. 结果返回来源、章节、原文位置、双路排名、向量分数、RRF 分数、重排分数和名次变化。

拒答门控由 20 条开发查询校准：最高向量分数至少为 0.48，或 BM25 最高分至少为 2.0 且查询词覆盖率至少为 0.67。80 条保留查询没有参与参数选择。

## 索引完整性与隐私

- 文本块与完整语料都由服务端重新计算 SHA-256；增量同步分别报告新增、更新、删除和未变化数量。
- 请求中的前端哈希只作元数据，不能替代服务端计算；语料指纹不一致时拒绝使用过期向量索引。
- BM25 不落盘。向量索引只在用户点击构建后写入 `server/data/qdrant`，可通过实验台或 `DELETE /api/index` 清除。
- Embedding、Qdrant、RRF 和 Cross-Encoder 均在本机运行，不调用云端模型。

## 真实保留集结果

数据集包含 15 份项目真实文档、90 条可回答查询和 10 条域外查询。固定的 80 条测试查询中有 75 条可回答、5 条不可回答。

| 模式 | Recall@1 | Recall@5 | MRR@5 | nDCG@5 | 拒答准确率 | P50 | P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.3067 | 0.6867 | 0.4480 | 0.5055 | 0.0000 | 126.029 ms | 143.993 ms |
| BGE vector | 0.2933 | 0.5800 | 0.3898 | 0.4346 | 1.0000 | 138.894 ms | 152.143 ms |
| RRF hybrid | 0.3600 | 0.7600 | 0.5107 | 0.5729 | 1.0000 | 343.746 ms | 380.933 ms |
| RRF + Cross-Encoder | 0.4533 | 0.7933 | 0.5891 | 0.6383 | 1.0000 | 1549.314 ms | 2011.542 ms |

RRF 相比 BM25 将 Recall@5 提高 0.0733，并把域外问题拒答从 0 提高到 1。Cross-Encoder 进一步改善首位命中与排序质量，但 CPU P50 增加约 1.2 秒。因此产品保留四种模式：默认低成本实验可用 BM25/RRF，高质量场景再启用重排。

开发参数选择证据见 `artifacts/evals/0.4.3-hybrid-dev-calibration.md`。

## API

- `GET /api/health`：服务、Embedding、索引与 Reranker 状态。
- `GET /api/index/status`：本机向量索引状态。
- `POST /api/index/sync`：构建或增量同步索引。
- `DELETE /api/index`：清除本机向量索引。
- `POST /api/retrieval/search`：支持 `keyword`、`vector`、`hybrid`、`hybrid_rerank`。

## 已知边界

- 评测来自真实项目文档，但查询是人工编写，不代表线上流量。
- 文档中版本号和相似章节很多，仍是主要失败来源；重排也会在否定句和强模板化章节上失误。
- 首次模型加载和索引构建不计入单查询延迟；低配 CPU 上重排可能更慢。
- 当前没有生成答案、引用合成、对话记忆或在线学习。
